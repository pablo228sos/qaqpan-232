# Security Policy

Qaqpan 232 processes untrusted text and screenshots in the browser. Security reports that could expose user data, enable code execution, bypass important protections, or otherwise create a concrete security risk should not be disclosed publicly before maintainers have had a reasonable chance to review them.

## Reporting a vulnerability

Please contact a maintainer privately through the contact information available on the repository owner's GitHub profile. Include:

- the affected component;
- clear reproduction steps;
- expected and actual behavior;
- impact;
- a minimal proof of concept when appropriate.

Do not include real victims' messages, credentials, banking data, authentication tokens, or other personal information in a report.

## Scope

Useful reports include vulnerabilities in the web application, build or deployment configuration, dependency handling, uploaded-image processing, or any behavior that could compromise confidentiality or integrity.

Model-quality issues such as false positives, false negatives, or weak detection patterns are not security vulnerabilities by themselves and should be reported as normal GitHub issues.
